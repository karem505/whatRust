# Optional WhatsApp Web notification-chime suppression

WhatsApp Web may play an internal notification sound in addition to the native
Windows notification sound generated by whatRust. This opt-in workaround
blocks the identified WhatsApp Web notification MP3. In Settings > Notifications,
enable "Mute WhatsApp Web notification chime" and restart whatRust to apply it.

## Evidence and implementation

A live WebView2 trace identified the audio source as
`https://static.whatsapp.net/rsrc.php/yW/r/BS_BUUXbKq5.mp3`, played multiple
times with different values of `navigator.userActivation.isActive`. The same
asset is referenced as WhatsApp Web's default notification sound by an existing
public sound replacement userscript:
https://greasyfork.org/en/scripts/483335-msn-notification-sound-for-whatsapp-web/code

When the opt-in setting is enabled, the injected script intercepts
`HTMLMediaElement.prototype.play` only on `https://web.whatsapp.com`, checks
that the receiver is `HTMLAudioElement`, and matches the HTTPS origin and
exact URL pathname of the identified MP3. Query parameters are ignored.
For this resource only, it returns a resolved Promise without calling the
original `play()`; all other media are passed through unchanged. The script
makes no network requests, stores nothing, and does not read messages.

This replaces the earlier heuristic based on `navigator.userActivation`
and in-memory learning: the same known resource is suppressed on the very first
play and after page reload, including when the user is clicking a notification.

## Limitations

- The third-party WhatsApp asset path may change; suppression will then cease
  without affecting other audio. Reidentify it before updating this match.
- Blocking `play()` changes the event sequence for that resource. The caller
  receives a resolved Promise but no real media playback/ended events.
- Only the HTML media `play()` path is intercepted; Web Audio API is unaffected.
- Existing sound options for other audio, calls, videos and voice messages are
  not intentionally modified, but changes in WhatsApp Web could cause regressions.
- Changes to the whatRust option require a restart because script injection is
  configured during WebView creation.

## Validation

Run `node --test tests/suppress-web-notification-sounds.test.js` and build whatRust.
Manually test notifications while typing, clicks on Windows toast notifications,
page reload, voice notes, videos, and call ringtones. Unit tests simulate only
`play()` and do not substitute for manual WebView2 testing.
