## whatRust v0.6.5

A follow-up to v0.6.4 for message notifications on Windows (#3, #32).

### What was still wrong

v0.6.4 let the WhatsApp page reach whatRust again, and Windows showed WhatsApp's test notification. A tester's log showed the remaining gap: when a real message arrived, WhatsApp never asked whatRust to notify. It raises those notifications outside the page, where whatRust's injected script can't see them.

### What changes

- **Windows:** whatRust now also takes over notifications at the WebView2 level, which sees notifications raised outside the page itself. WebView2's notification permission is allowed, and every notification it receives is shown as a whatRust toast. These toasts still respect the app lock and the Notifications setting.
- **Every platform:** if a chat becomes unread while the window isn't in front of you, and no notification arrived for it within a few seconds, whatRust shows a short "New message" alert. The alert contains no message content, and it stays silent whenever WhatsApp's own notification came through.
- **One notification per message:** the same alert arriving by two routes is shown once.
- **Diagnostics:** the log (`%LOCALAPPDATA%\whatRust\logs\whatrust.log` on Windows) now records which route each notification took, and whether WhatsApp installed a service worker. It records names of routes only, never message content.

### If notifications still don't appear

Please add a comment on #3 with the `notify:` and `notif path:` lines from the log, and say whether the window was minimized, hidden in the tray, or open on another chat.

### Install or update

```bash
# Linux (AppImage) and macOS
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install.sh | sh
# Linux (Flatpak)
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install-flatpak.sh | sh
```

On Windows, run the `x64-setup.exe` or `.msi` below.
