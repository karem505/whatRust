## whatRust v0.6.6

A small fix-up release from end-to-end testing of v0.6.5 on fresh Linux and Windows machines.

### Linux AppImage behind a proxy

- **Fixed:** with `HTTPS_PROXY`/`HTTP_PROXY`-style environment variables set (common behind corporate proxies), the v0.6.4 and v0.6.5 AppImages showed "WebKit encountered an internal error" instead of WhatsApp. Newer Tauri bundlers pack two proxy modules into the AppImage that crash WebKit's network process when those variables are set. The release build now removes them, the way the libwayland libraries are removed for #22. The `.deb` and Flatpak were never affected.
- The AppImage's internal folders also get normal permissions again.

### Linux and macOS

- **Fixed:** a harmless but noisy error in the WhatsApp page at every start (`is_permission_granted not allowed`). The notification plugin's read-only permission check is now allowed, while its own notify command stays blocked, so notifications still always go through whatRust's lock-aware path.

### Verified on a fresh machine

Tested with the published v0.6.5 builds before this release:
- **Windows:** silent install, `whatsapp://` registration, launch, a page link opening in the default browser, a `whatsapp://` link reaching the running app, and the notification hook.
- **Linux `.deb`:** the same checks.

Message notifications on Windows were confirmed by a user in #3.

### Install or update

```bash
# Linux (AppImage) and macOS
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install.sh | sh
# Linux (Flatpak)
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install-flatpak.sh | sh
```

On Windows, run the `x64-setup.exe` or `.msi` below.
