## whatRust v0.7.1

**One sound stream on Linux, Arabic, Indonesian and Spanish, a System/Light/Dark theme, account cards, per-account notifications, a quicker unread count, a Relaunch button, and fixes for Windows downloads, Windows memory in the tray and GNOME notification banners.**

Thanks to everyone who sent code, translations, reports and screenshots this round.

### New

- **Interface in Arabic, Indonesian and Spanish.** Settings → Appearance → **Language**. Arabic lays the Settings window out right to left. A fresh install picks the language from your system. (#93, thanks @brianfauzanlukman for the request and the offer to review Indonesian; Spanish in #127, thanks @Hans183)
- **System / Light / Dark theme** for whatRust's own pages. WhatsApp follows it when its theme is set to "System default". (#126, thanks @Hans183)
- **Silence WhatsApp Web's own chime** without touching the system notification sound. (#125, thanks @R4wd0g)
- **Turn notifications off for one account.** Settings → Accounts → the account's menu → **Turn notifications off for this account**. No pop-ups and no WhatsApp tones from that account; its unread count still shows. (#118, #103, thanks @tycheed)
- **Account cards.** The account picker shows one card per account (photo or initial, name, unread count) plus an **Add account** card. Turn on **Show the profile picker at startup** to start on it with more than one account in one window. (#102, thanks @schoolerani-spec)
- **Hide unread counts.** Settings → **Show unread counts** off removes the number from the tray icon, the dock or taskbar badge, the window title and the account lists. Notifications are not affected. (#100, thanks @schoolerani-spec)
- **Relaunch** button at the start of the Settings bottom bar. (#131, thanks @schoolerani-spec)
- **Pause the activity log.** Diagnosis → Activity this session → **Record activity**, plus a **Clear** button. (#99, thanks @schoolerani-spec)
- **The logo in the top bar opens the account menu**, and with WhatsApp's header left untouched the top bar shows at once instead of after the chat list loads. (#128, #129, thanks @schoolerani-spec)

### Fixes

- **Linux: one sound stream.** WebKitGTK opened a separate audio stream for every sound WhatsApp played and then paused (alert tones and every voice note you listened to) and for every Web Audio context, so the volume mixer filled with «whatRust» entries and the background threads added up. A sound now gives its stream back 1.5 seconds after it stops, voice notes included (they keep their length and resume where you paused them), and WhatsApp's audio contexts share one. When nothing is playing there is no whatRust stream at all. This also helps the slow CPU climb over long sessions (#121). The GNOME media player entry (#120) is a separate engine behaviour and is not changed by this.
- **Unread count follows WhatsApp at once**, including **Mark all as read**: it is re-read within a fraction of a second of a change instead of up to two seconds later, and counts like `(1,234)` or a title with direction marks are no longer read as 0. (#98, thanks @schoolerani-spec)
- **Linux (GNOME, .deb/.rpm/AppImage/Flatpak): notifications pop up as banners.** They now name the installed desktop file, so GNOME knows which app sent them, and use normal urgency. (#119, thanks @i-bahnasy for the dbus capture)
- **Windows: every download in a session gets its Save dialog.** Files are downloaded to a private folder first and the Save dialog opens once the file is complete, so a second or third download no longer fails silently. (#122, thanks @panjidwiprasetya-ux for the detailed log)
- **Windows: less memory while hidden in the tray.** When the window is hidden or minimised, WebView2 is asked to trim its memory; messages and notifications keep arriving. (#101, thanks @schoolerani-spec)

### Also

- README: a **Privacy** section (no telemetry; only WhatsApp Web and GitHub's release API) and a **Code signing policy**. whatRust has applied to the SignPath Foundation for free code signing of the Windows installers, which should end the antivirus warnings on the unsigned `.exe` (#70, thanks @Iruhan21).
- #132 (opening a PDF in Acrobat): the error comes from the PDF viewer's "Edit in Acrobat" menu, which opens Adobe's website. Use the download's **Open** button, or save the file and open it from your folder; details in the issue.
