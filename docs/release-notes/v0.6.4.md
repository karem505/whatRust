## whatRust v0.6.4

This release fixes notifications on every platform, makes links in chats open, adds support for `whatsapp://` links, fixes drag and drop on Windows, enables calls on macOS, and fixes the blank AppImage window on current Linux distributions.

### Notifications and the unread badge (#3, #32)

- **Notifications work again.** Since the move to Tauri 2.11, every call from the WhatsApp page to whatRust (`notify`, the unread count, diagnostics) was silently refused by Tauri's permission check. The page is now granted exactly the commands it needs. New tests guard this, so it can't silently regress.
- On Windows, toasts are raised directly through WinRT. The result is logged to `%LOCALAPPDATA%\whatRust\logs\whatrust.log`, and clicking a toast brings whatRust to the front.
- The tray's unread badge counts messages again.
- While the app is locked, nothing on the page can trigger a notification preview.

### Links (#30, #23)

- **Links in chats open.** Web, email and phone links go to your default browser or app. WhatsApp links (`wa.me`, group invites) open inside whatRust.
- **`whatsapp://` links.** "Open app" and click-to-chat buttons on websites now open the chat in whatRust, with any message pre-filled. The scheme is registered by the `.deb`, the Flatpak, the Windows installers, the macOS app, and the one-line AppImage installer.

### Drag and drop on Windows (#31)

- Dropping files onto a chat works on Windows again. Drops now go straight to WhatsApp Web, so you get WhatsApp's own drop zone, the same as in a browser.

### Calls (#15)

- **macOS:** whatRust now identifies itself as the Safari release that ships with your macOS, which is what the system webview really is. WhatsApp then uses its Safari calling path, which a user confirmed makes voice and video calls work.
- **Windows:** WhatsApp Web doesn't offer calls to Windows browsers at all, and whatRust won't disguise your OS to get around that. Use the official app for calls on Windows.
- **Linux:** unchanged. Most distributions build WebKitGTK without WebRTC.

### Linux AppImage (#22)

- Fixes the blank window with `EGL_BAD_PARAMETER` on distributions with a recent Mesa. The AppImage no longer bundles the build system's old `libwayland-*` libraries, so the system's own copies are used.

### Downloads and Settings (#21)

- When a download finishes, the window shows a toast with **Open** and **Show in folder**, or says the download failed. Programs and installers are only ever shown in their folder, never opened.
- Settings has a cleaner layout, in the style of GNOME's preferences: grouped rows with switches, following the system light/dark theme.

### Install or update

```bash
# Linux (AppImage) and macOS
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install.sh | sh
# Linux (Flatpak)
curl -fsSL https://raw.githubusercontent.com/karem505/whatRust/master/install-flatpak.sh | sh
```

On Windows, run the `x64-setup.exe` or `.msi` below.
